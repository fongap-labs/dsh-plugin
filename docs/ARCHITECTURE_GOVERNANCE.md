# 架构治理

本规范仅约束插件产品实现。组织级治理、执行权限、门禁及发布来源证明由 [Action Worker](https://github.com/fongap-labs/action-worker/blob/main/docs/ARCHITECTURE_GOVERNANCE.md) 唯一维护。

## 权威与职责

仓库级产品、包依赖和原生宿主权威以 [机器合同](../projects/architecture.json) 为准；产品内部职责以各产品的 architecture-mece.json 为准；就绪状态以对应 feature-readiness.json 和实际证据为准。架构设计不等于已实现，已实现不等于已验收。

- Suite：通用交互、会话体验、任务意图和通用助手协作策略；不拥有 Coding 专项编排。未来通用 Agent 角色或任务分级须经独立产品评估，不得据此新增第二个执行器。
- Code：编码路由、编辑、仓库操作、验证交付及 Coding 专项协作策略；不替代宿主 Agent。
- Shared：仅中立基础能力，不持有产品状态、业务策略或独立发布目标。
- Host：执行、原生会话、模型、MCP 配置、凭据和最终授权；插件只通过已确认的公开契约调用。
- Action Worker：中央执行和治理；插件仓库提供产品源码、构建声明及经中央批准的不可外置测试；新增可外置测试统一进入中央测试包。

## 小内核、大框架

内核仅保留注册、生命周期、失败隔离及回滚。组合入口注入依赖；业务功能独立持有策略；适配层封装外部契约。禁止业务逻辑倒灌内核、跨插件内部引用、Shared 反向依赖产品、为同一能力新增平行实现。

正确范例：缺少宿主公开能力时只禁用该功能，保持宿主原生行为。错误范例：以私有 DOM、Store、凭据读取、方法劫持或第二套运行时实现缺失能力。

源码拆分按业务所有权，不按行数；Suite 客户端必须保持单一可加载模块、宿主 React 及 Cordis 生命周期。现存跨层调用、转发文件和大型模块是迁移对象，不得扩大；变更时保留真实行为测试和发布产物契约。

## 变更与验证

新增能力先确定唯一所有者、公开宿主接口、权限、失败回退、卸载及验收，再修改合同、实现与回归测试。禁止重新引入已移除的网络代理、Vision Bridge、宿主源码 Patch、私有凭据读取或重复执行权威。

仓库结构和直接跨包依赖由 [中央架构测试](https://github.com/fongap-labs/action-worker/blob/main/tests/packs/plugins/plugins-architecture-governance-test.mjs) 自动检查；现有产品测试继续验证行为、注册、权限和产物。新增架构检查不得降低已有门禁。完整内部导入图、循环依赖及适配层迁移须在实际清查后逐步加强，不能把未实现的约束描述为已自动验证。

新增普通插件应通过新增包、产品合同、发布清单及对应测试接入；不修改其他产品内核，不在 Action Worker 新增项目专属执行分支。
