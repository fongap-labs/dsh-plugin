# 免费模型网关的客户端保护

本功能让 Delta Suite 在使用免费 AI 网关时限制重复请求和同时推理的数量，并让客户端与网关共用提交前的截止时间。它通过 Harness 的公开事件工作，默认不启用；不修改宿主核心文件，也不改变工具审批结论。

## 配置与启用

安装包含本功能的 Delta Suite 后，把仓库的 [配置示例](../examples/free-gateway.patch.yml) 合并到实际 Profile 的 `cordis.patch.yml`。把 `gateway` 换成模型设置里的 provider ID，把 `https://gateway.example.com` 换成网关的 HTTPS 来源地址；来源地址不带 `/v1`、路径或凭据。`Code-Max`、`Code-Ultra` 也需要与实际逻辑模型名称完全一致。

配置覆盖的是整个插件行的 `config`，不是深度合并。先保留原行的其他自定义值，再加入示例字段。示例中的压缩、子 Agent 和输出裁剪行是可选调优，应按实际宿主版本核对配置名称后使用。

| 字段 | 默认值 | 作用 |
| --- | --- | --- |
| `providers` | 必填 | 需要保护的 provider ID 列表 |
| `origins` | 必填 | 允许接收路由头的 HTTPS 来源列表 |
| `stepBudgetMs` | 180000 | 一步开始后，共享给队列等待和所有提交前重试的时间 |
| `auxiliaryBudgetMs` | 90000 | 压缩、自动审查等辅助调用的提交前时间 |
| `maxConcurrent` | 1 | 本插件实例同时进行的网关推理数 |
| `maxQueued` | 16 | 等待推理的最大请求数；满后明确停止 |
| `maxClientRetries` | 1 | 一步最多允许宿主原生重试的次数 |
| `requireHeaderSupport` | false | 要求适配器实际调用请求头接口；缺失时停止交付输出并报告宿主不支持 |

所有字段先验证再注册。保护只影响配置的 provider；路由头只发送到配置的来源。没有 `gatewayReliability` 时沿用宿主行为。基础保护使用 `agent/pre-step`、`agent/request-error`、`llm/stream` 和 `session/event`。完整的跨请求截止时间与亲和提示另需 `llm-pi-ai/request-headers`，已发布的 `llm-pi-ai@0.2.1-rc.3` 尚无该接口；源码主干已有，但不能据此认定安装包可用。

实际调用未观察到请求头接口时，宿主日志会明确警告：队列、错误识别和重试次数限制仍生效，跨请求的网关截止时间与亲和提示不可用；本地时间检查不能中断已经开始的远端调用。需要严格保证时设置 `requireHeaderSupport: true`，缺失接口会停止交付成功输出并报告 `GATEWAY_HOST_UNSUPPORTED`。检测发生在适配器开始调用之后，首个探测请求可能已产生上游工作，因此应先在测试环境验证宿主版本。

## 重试与流式输出

Cloudflare 1102 和明确标记不可重试的结构化错误停止原样重试。pi-ai 可能把 HTTP 错误正文折叠成一段字符串；模块只解析其中保留的 JSON 问题响应，不把任意模型文本当作故障指令。Chat/Messages 的网关 `error.details.retry_after_ms` 会恢复为宿主原生的等待提示。过长的等待或已过期的步骤不进入新一轮请求；等待和重试事件仍由宿主已有的重试插件记录。

Responses 协议保持标准错误正文，恢复元数据位于响应头；使用这一协议的适配器需要保留响应头才能完整处理网关提示。当前 pi-ai 折叠错误正文的路径不能恢复已丢弃的响应头，本模块不声称三种客户端协议具有相同的元数据支持。

仅在尚无有效输出时，特定的畸形 SSE 错误才归入可有限重试的传输错误。已经输出文本、推理内容或工具参数后发生错误时，返回 `GATEWAY_PARTIAL_RESPONSE` 并停止自动重放；不补造完成帧，不执行残缺工具调用。恢复时先依据宿主 Session 记录核对文件、提交和其他副作用，再继续任务。

一次步骤中的所有客户端重试复用同一个 `x-gateway-deadline-ms`。网关需要支持该请求头；它只缩短首个有效输出提交前的回退窗口，不延长服务端预算，也不限制已经开始的正常流式生成。流提交后的取消、网络超时和完成校验仍由原生适配器负责。不要把这个设置理解为所有请求都能在固定时间内完成。

## 并发、亲和与审批

主模型、压缩与自动审查共享一个 FIFO 推理队列，排队取消和超时不会调用模型。等待原因写入宿主日志。这个队列只覆盖当前插件实例，其他进程和其他客户端仍需各自限制并发；网关 isolate 内的限制同样不构成全局配额。

普通对话发送稳定的 `x-session-id`；辅助调用在会话 ID 后附加用途，避免混用亲和记录。亲和是路由提示，不能固定模型或保证缓存命中。模块不会改写 provider、模型、消息或工具定义。

自动审查的授权和拒绝仍由宿主决定。本模块把审查调用纳入队列和资源错误处理，不缓存允许结论，也不在模型不可用时执行工具。当前 Harness 的 `AUTO_REVIEW_FAILED` 与 `AUTO_REVIEW_DENIED` 应分别展示；独立审查模型、确定性授权规则或缩减审查输入需要在其所属的原生审查组件中实施并单独验证，不能由流量保护插件替代。

卸载模块时取消排队、移除监听并清理本地步骤状态；已开始的模型调用继续遵循原生生命周期。任务和工具记录仍由 Harness Session 持久化，不新建第二份任务状态权威。重启后依靠现有 Session/checkpoint 恢复，新的一轮拥有新的截止时间。

## 长上下文调优与验证

示例对两个明确的逻辑模型提前触发压缩、保留最近 8192 token，并限制摘要输出和额外压缩次数。阈值按模型声明的上下文比例计算，例如 262144 窗口的 0.2 约为 52k；真实阈值还受输出预留和 headroom 影响。先核对可回退模型的真实容量，再做对比测试。原生摘要保留目标、约束、文件、错误、待办和下一步，压缩失败时沿用原生的事务性提交行为，不删除上一版有效 checkpoint。

首次启用使用不含敏感数据的任务验证：检查同一步两次请求的截止时间相同、1102 不重发、取消排队不调用模型、局部断流不执行工具、模块卸载后恢复原生行为。记录实际完成率、调用放大、Worker CPU 和完整交付率；不预设缓存或性能改善百分比。
