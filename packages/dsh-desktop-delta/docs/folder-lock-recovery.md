# Delta Desktop 文件夹写入锁恢复

文件夹数据保存在用户目录的 `~/.dsh-ui-delta/folders.json`，修改时使用同目录下的 `folders.json.lock` 独占目录，避免多个 DSH 进程同时覆盖文件。

## 异常退出

每次成功取得锁后，Delta 在锁目录写入包含当前 PID 和随机所有权标识的 `owner.json`。正常完成或异常抛错时会释放锁。进程在写入过程中崩溃，则锁目录可能遗留。

后续更新碰到已有锁时，只在下列条件**同时满足**的情况下自动恢复：

- 获得独占的 `folders.json.lock.recovery` 恢复锁；
- `owner.json` 格式完整、持有有效 PID 和所有权标识；
- 操作系统明确报告该 PID 已不存在（`ESRCH`）；
- 锁目录不存在其他未知内容。

即使锁已经存在很久，只要 PID 仍存活或权限不允许确认进程状态，**不会仅凭时间过期就抢锁**。恢复锁有竞争或元数据不存在、损坏、无法确认时，更新仍报冲突而不修改 `folders.json`。

## 无法自动恢复

若崩溃发生在创建锁目录与写入 `owner.json` 之间、在清理锁的极短窗口内，或恢复期间本身崩溃，则状态可能无法自动判断。这时必须人工确认所有 DSH 进程已停止，并备份 `folders.json`，再检查锁目录后决定是否手动清理。**不要在有任何 DSH 进程运行时强行删除锁目录，也不要删除 `folders.json`。**

新的恢复逻辑不使用额外的远程服务、不传输文件夹内容，不修改已经存在的会话与分组。锁恢复成功后仍执行已有的修订版本检查；写入成功与否由原有 API 返回值决定。
