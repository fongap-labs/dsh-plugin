# Delta Desktop 插件架构与启动协议

## 必须保持的约束

1. **插件安装/运行**：`@fongap-labs/dsh-desktop-delta` 通过 DSH 插件清单、Cordis Host 生命周期、内置 Web 客户端加载；不是第二份独立 Harness，也不是必需的 Tauri/Electron 应用。
2. **Delta 优先，原生故障回退**：官方 DSH 完成登录 Cookie 交换后，插件入口验证受保护的 Delta 页面；验证时隐藏原生聊天，成功则用同一窗口导航替换原生文档。独立页面在首次启动时还需要 Session RPC 与 Gateway 事件流双重就绪，15 秒未就绪则返回原生根页，并附带单次 `delta-native-fallback=1` 标记避免重定向循环。启动成功后不再因短暂网络重连自动切回原生。
3. **桌面功能底座**：Delta 不限于网页 UI，Host 可扩展搜索、记忆、审批、工具与其他受管能力；应按功能拆分，不把新能力写进启动重定向器。
4. **解耦**：`src/host/harness-adapter.ts` 收口 DSH 的 Web 路由、Cookie admission 与生命周期注册；独立页面仅通过该适配器与受支持的 Gateway RPC/事件流通信。禁止直读 Harness 私有 SQLite、修改原生 React 组件树、复制登录令牌、拦截底层原生启动器。

## 当前限制

插件只能在官方客户端加载插件后介入，**不能在 DSH/Electron 启动之前停止原生进程初始化**。这里的“关闭原生界面”是：成功切换后原生网页被同窗口替换且不并行活动；不是通过插件终止宿主窗口或引擎。如果未来要在宿主启动前直接显示 Delta，需要一个由 DSH 正式支持的启动 URL/窗口入口适配器。

独立页面目前仅实现基础聊天、Session、Gateway 事件流与人工工具审批；不能宣称已替代原生所有设置、模型和工具能力。默认回退原生时应保留 DeepSeek 原生模型配置/提示；Session Log 上传、遥测、插件清单上传及产品分析禁用策略不得随回退恢复。

## 验收门禁

- 代码侧：单元测试、TypeScript 检查、中央 CI 全绿。
- 真实 Windows DSH：已登录启动、未登录 Cookie 交换、缺失插件、Gateway 不可达、会话 RPC 失败、首次握手超时、成功后短时断线、更新与停用插件。
- 正式发布前必须证明无双界面并行、无导航循环，且原生回退功能可用于修复模型配置。

旧版本可能需要不同的 DSH 页面入口；不应通过修改或伪造 Host Cookie 来兼容。
